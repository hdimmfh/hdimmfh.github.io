🔍 **Does CPU Memory Always Move into GPU HBM?**

> Not anymore. On conventional PCIe systems, GPU access to managed memory commonly results in page migration into HBM. Grace Hopper and Grace Blackwell introduce another option: coherent access to CPU memory over NVLink-C2C.

---

## ① Traditional Unified Memory

Unified Memory provides a single virtual address space, but CPU DRAM and GPU HBM are still physically separate. When the GPU first accesses a managed page, CUDA UVM resolves the access by updating page mappings and, when necessary, migrating the page into GPU memory.

```cpp
float* data;
cudaMallocManaged(&data, size);
initialize_on_cpu(data);
kernel<<<blocks, threads>>>(data);
```

On a conventional PCIe GPU, the runtime typically prepares GPU execution by migrating managed pages into HBM.

---

## ② Grace Changes the Model

Grace Hopper and Grace Blackwell keep the same Unified Memory API. What changes is the hardware. Instead of requiring migration before every GPU access, the GPU can fetch cache lines directly from coherent CPU LPDDR through NVLink-C2C.

```
GPU SM
    ↓
GPU MMU / TLB
    ↓
NVLink-C2C
    ↓
Grace LPDDR
    ↓
GPU L2 Cache
```

HBM migration still exists, but it is now an optimization for locality rather than a correctness requirement.

---

## ③ What Does `cudaMemPrefetchAsync()` Actually Mean?

`cudaMemPrefetchAsync()` does **not** simply mean "copy this memory into GPU HBM."
Instead, it tells CUDA Runtime:

> "The GPU is expected to access this memory next. Prepare it."

How CUDA prepares the memory depends on the platform.

| PCIe GPU | Grace Superchip |
|-----------|-----------------|
| Migrate pages into GPU HBM | Keep pages in CPU memory, prepare coherent mappings, or migrate if beneficial |

The application always calls the same API. Only the runtime behavior changes.

---

## ④ Key Takeaway

The Unified Memory programming model has not changed. What changed is how the hardware satisfies a GPU memory access.

**Traditional PCIe**

```
CPU DRAM
    ↓
Page Migration
    ↓
GPU HBM
    ↓
GPU
```

**Grace Superchip**

```
CPU LPDDR
      ├── Direct coherent access
      └── Optional HBM migration
              ↓
             GPU
```

Grace does not eliminate page migration. It makes page migration **optional**, allowing CUDA Runtime to choose between remote coherent access and local HBM placement according to runtime behavior.

---

## TL;DR

- Unified Memory provides one virtual address space, not one physical memory.
- PCIe systems commonly migrate managed pages into GPU HBM.
- Grace GPUs can directly access coherent CPU memory over NVLink-C2C.
- `cudaMemPrefetchAsync()` is a placement hint, not a copy command.
- CUDA Runtime decides whether to migrate, map, or access memory coherently depending on the platform.
